# Track 5 — Securing and Governing Agentic Workflows

> **Personal study repo — not affiliated with Google Cloud.** Official guidance: [cloud.google.com/learn/certification/agentic-architect](https://cloud.google.com/learn/certification/agentic-architect) · [Disclaimer](../../DISCLAIMER.md)

This track covers **Exam Section 5 (~15% direct weight, plus 30–35% cross-cutting IAM, identity, connector auth, and security constraints across the entire exam)**. Every enterprise agent question tests whether you enforce least-privilege predefined IAM roles across projects, avoid static credentials, isolate user-delegated OAuth 2.0 connector auth from workload identity, cap blast radius with Principal Access Boundaries (PAB), redact HIPAA PHI via Model Armor + Sensitive Data Protection (SDP), and govern A2A/MCP traffic at an Agent Gateway.

## Labs in this track

* **[Lab 16: IAM Least-Privilege, Agent Identity, Connector Auth & PAB](lab_16_agent_identity_and_auth/README.md)** *(Objectives 5.1, 3.2 & cross-cutting IAM)*: Safe credential provisioning via **Agent Identity** (`GcpAuthProvider`, `GcpAuthProviderScheme`, `AuthProviderCredentialsServiceClient`), **Auth Manager OAuth 2.0** (`OAuth2Auth`) & **Gemini Enterprise Connector Auth** (`IAMConnectorCredentialsServiceClient`) 3LO user consent vs. workload identity, **Cross-Project Least-Privilege IAM** (`roles/aiplatform.user`, `roles/discoveryengine.viewer`, `roles/modelarmor.user`, `roles/run.invoker`, host-project `roles/bigquery.jobUser` + dataset `roles/bigquery.dataViewer`), and **Principal Access Boundary (PAB)** (`Effective Access = IAM Allow ∩ PAB`).
* **[Lab 17: Model Armor with Sensitive Data Protection (SDP), Gateway Pattern & HITL](lab_17_model_armor_and_hitl/README.md)** *(Objectives 5.1 & 5.2)*: Instantiates `google.cloud.modelarmor_v1` (`FilterConfig`, `SdpFilterSettings`, `SdpBasicConfig` vs. `SdpAdvancedConfig` with `inspect_template` + `deidentify_template` for HIPAA PHI redaction/tokenization, `PiAndJailbreakFilterSettings`, `MaliciousUriFilterSettings`) alongside ADK's fail-closed `ModelArmorPlugin`, contrasts **Centralized Agent Gateway Model Armor** vs. **In-Agent Plugin**, and wires HITL (`request_input`, `get_user_choice`) for irreversible customer/clinical actions.
* **[Lab 18: Agent Governance, Agent Gateway + Model Armor Perimeter & Agent Registry](lab_18_governance_gateway_registry/README.md)** *(Objectives 5.1 & 5.2)*: Combines the **Agent Gateway + Model Armor Gateway Pattern** (centralized ingress/egress proxy screening prompts, A2A tasks, and MCP tool outputs, enforcing token/RPM quotas, mTLS/OAuth validation, and end-user token propagation for Document-Level ACLs) with **`AgentRegistry`** catalog attestation (`get_mcp_toolset`, `get_remote_a2a_agent`).
* **[Lab 20: End-to-End Regulated (HIPAA / Financial) AI Threat Defense Blueprint](lab_20_e2e_ai_threat_defense/README.md)** *(Objectives 5.1 & 5.2)*: Unifies Cross-Project Least-Privilege IAM + Agent Identity + PAB + Agent Gateway + Model Armor w/ `SdpAdvancedConfig` PHI De-identification + Agent Registry + Zero-Retention Telemetry (`ContentCapturingMode.NO_CONTENT`) against multi-vector enterprise attacks.
